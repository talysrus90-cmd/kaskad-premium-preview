# КАСКАД — разбор окна «Сбербанк / Телефон» при звонке с сайта

Дата: 2026-11-10. Статус: исследование + отдельный диагностический тест, основная кнопка не изменена.

## Подтверждённые факты

- На присланных владельцем скриншотах Android показывает системное окно «Открыть в приложении» с вариантами «Сбербанк — Перевести по номеру» и «Телефон».
- Это не HTML-модальное окно «КАСКАДА»: оно появляется после перехода по телефонной ссылке.
- Текущая основная кнопка на GitHub Pages использует стандартный `href="tel:+79284062212"`.
- Изменения размеров и анимации кнопки на выбор приложений не влияют.
- Предыдущая попытка `intent:+79284062212#Intent;scheme=tel;action=android.intent.action.DIAL;end` без указания пакета **не решила проблему** в браузере владельца.
- По внешнему виду присланных скриншотов страница, вероятно, открыта во встроенном браузере/Custom Tab, а не в полноэкранной вкладке Chrome. Для разных браузеров правила обработки внешних схем отличаются; это гипотеза, а не подтверждение модели браузера.
- На подключённом тестовом Redmi команда `ACTION_DIAL tel:+79284062212` разрешается в штатную звонилку `com.android.contacts`; тест на устройстве Samsung владельца выполнить удалённо не удалось.

## Почему это происходит

Android использует механизм Intent resolution. Если несколько приложений заявили поддержку соответствующей схемы/действия, система может показать chooser. Фраза «Перевести по номеру» на скриншоте свидетельствует, что банковское приложение предложено как обработчик ссылки на номер; сайт сам не добавляет банк.

Разница с нативным приложением (например, Авито): Android-код приложения может вызывать `ACTION_DIAL` и, где уместно, `setPackage`; HTML-ссылка `tel:` делегирует работу браузеру, и он сам определяет используемый Intent.

## Документированные ограничения

1. `ACTION_DIAL` открывает экран набора, но не инициирует разговор автоматически. `ACTION_CALL` требует `CALL_PHONE`, недоступного обычной веб-странице.
2. Chrome поддерживает URL `intent:` с `action`, `package` и `browser_fallback_url`, но может отклонить переход в зависимости от браузера, отсутствия пользовательского нажатия и категории BROWSABLE.
3. Встроенные WebView и Custom Tab могут обрабатывать или блокировать специальные URL иначе.
4. Не существует универсального HTML/JS-средства принудительно назначить dialer для всех Android и немедленно совершить обычный телефонный звонок.

## Новый проверочный вариант (НЕ подключён к основной кнопке)

Тестовая страница: https://talysrus90-cmd.github.io/kaskad-premium-preview/tests/samsung-dial.html

Используется `intent:+79284062212#Intent;scheme=tel;action=android.intent.action.DIAL;package=com.samsung.android.dialer;S.browser_fallback_url=<encoded test page>?unsupported=1;end`.

Цель: попросить браузер открыть **штатный пакет Samsung**, исключая банковское приложение из кандидатов. У теста есть HTTPS-fallback, не создающий звонок и не запускающий банк. Проверено только наличие страницы и корректного Android Intent-синтаксиса в коде. Действительное поведение в браузере владельца пока не подтверждено.

**Критерий приёмки:** при нажатии на Samsung появляется экран набора с номером КАСКАД, без выбора банковского приложения. Если появляется системный chooser или тестовая страница остаётся без перехода — вариант не принимать. Если проходит, внедрять условно для Samsung+Chromium с обычным `tel:` для остальных; поддерживать fallback. Не обещать полной совместимости без испытаний на других браузерах.

## Важное

Нельзя считать проблему решённой только после изменения исходного кода. Не менять основной коммерческий сценарий на неподтверждённый эксперимент. Пользователь должен подтвердить результат теста на своём Samsung; до этого на основном сайте остаётся совместимая ссылка `tel:`.

## Результат после проверки владельцем — 10.11.2026

Владелец лично проверил отдельную страницу `tests/samsung-dial.html` на своём Samsung и подтвердил: открылось обычное приложение телефона **без Сбербанка**. Это подтверждение касается именно экспериментальной ссылки, а не автоматического совершения звонка.

Проверенный Intent перенесён непосредственно в `href` основной красной кнопки `index.html` (не только в обработчик JavaScript). Подключён `call-routing.js?v=samsung-dial-20261110-v2`: для подтверждённых Samsung/Chromium сохраняется прямой Samsung ACTION_DIAL, для iPhone и опознанных других моделей — обычный `tel:`. У нераспознанных Android возможна резервная страница `call.html`.

Проверены опубликованные HTML и JS по HTTPS, синтаксис JS (`node --check`), пять сценариев модели устройства (Samsung с обычным и сокращённым User-Agent, Pixel, iPhone, Firefox) и все 30 ресурсов предварительного кэша PWA (`HTTP 200`, ошибок нет). Версия Service Worker повышена до `kaskad-pwa-20261110-samsung-dial-v2`.

**Проверка на основной кнопке владельца:** ещё не получено отдельного подтверждения после переноса. Фактическое открытие телефонной программы и совершение звонка — разные действия; автоматического вызова сайт не делает. Не утверждать совместимость со всеми браузерами и устройствами без их тестирования.
