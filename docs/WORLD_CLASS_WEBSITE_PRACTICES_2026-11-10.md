## Принцип

**Минимум усилий посетителя → реальный полезный результат → понятная цена/следующий шаг → достоверное поступление обращения менеджеру.** Ни анимации, ни ИИ-рендеры, ни красивые обещания не заменяют проверенную передачу заявки.

## Фактическое состояние «КАСКАДА» (аудит HTML на 10.11.2026)

Уже присутствуют: реальные мобильные сценарии и адаптивная шапка; подтверждённая владельцем прямой набор Samsung (не менять без проверки); 4 направления услуг; галереи, «до и после»; калькулятор; этапы работ; FAQ с офертой и согласием; редактор письма с сохранением предпочитаемого сервиса; PWA кэш. Главная HTML ~121 KB; 16 тегов изображения, 12 с lazy-load. Эти показатели **не являются** Lighthouse-оценкой скорости.

**Главная незавершённая бизнес-функция:** автоматический приём заявок на `kaskad123ai@mail.ru`. GitHub Pages — статический хостинг. `preview-runtime.js` содержит демо-обработку, `/api/leads` недоступен. Подготовленный черновик требует явной отправки почтовым клиентом. Только реальный серверный обработчик/публикуемая форма с уведомлениями даст автоматическое получение. **Не показывать «отправлено» до получения подтверждения сервиса.**

## Этап 1 — критический, выполнить до рекламы и продвижения

1. Авторизовать официальный Яндекс ID владельца (без передачи пароля в чат), создать общедоступную форму «КАСКАД — заявка и предварительный расчёт».
2. Одна форма с условной логикой, общими полями: вид работы (дом/ремонт/интерьер/проекты), имя, телефон, краткая задача; необязательно: город, площадь, бюджет, срок, фото/план. Обязательное отдельное информированное согласие ПДн и ссылки на законные документы. Оформить данные оператора, политику и размещение до запуска. Убрать ненужные вопросы с первого экрана.
3. Настроить email-уведомление на `kaskad123ai@mail.ru` через стандартное действие «Почта» и встроить iframe. По официальной документации Яндекс Форм поддерживаются публикация iframe и уведомление при отправке. Источники: https://yandex.ru/support/forms/ru/publish , https://yandex.ru/support/forms/ru/send-mail .
4. Привести все точки входа («Обсудить проект», «Подготовить заявку», «Расчёт», «Задать вопрос», формы ремонта/строительства) к единому механизму приёма: передать тип обращения и контекст. При использовании готового iframe проверить перенос данных и не считать его автоматически поддерживаемым без тестов.
5. Проверить: три тестовые формы, факт ответа в интерфейсе сервиса, письмо на `kaskad123ai@mail.ru` (входящие и спам), корректные согласия, ошибки/повтор, сохранение данных при сбое; мобильный Samsung/Chrome, iPhone/Safari. Если нет подтверждения — не объявлять доставку.
6. Перед отправкой реальных контактов выполнить юридическую проверку по ст.18(5) Федерального закона №152-ФЗ, включая требования к обработке ПДн граждан РФ и сведения об операторе; не подключать зарубежные внешние формы без проверки обработки и хранения.

**Текущий блокер:** на подключённом Windows-ПК при открытии https://forms.yandex.ru/ система перевела на `passport.yandex.ru` — требуется вход в Яндекс ID. Форма ещё **не создана**, уведомления ещё **не протестированы**. Подробно: `docs/LEAD_INTAKE_LAUNCH_CHECKLIST.md`.

## Этап 2 — простые улучшения без платных API

- Компактная неагрессивная мобильная нижняя панель: «Позвонить» (проверенный Samsung Intent), «Рассчитать», «Оставить заявку». Не дублировать кнопки под героем; не закрывать контент и не мешать клавиатуре.
- Три быстрых сценария: «Построить дом», «Сделать ремонт», «Проект/смета»; вариант «Просто спросить». Изменять поля по выбранному сценарию, использовать заполненные сведения из калькулятора, не заставлять повторять.
- Объяснимый бюджет: диапазон ₽, что входит/не входит, откуда цена, дата актуальности и пометка «предварительно; не является офертой». Не выдавать расчёт за договорную смету.
- Карточки реальных завершённых работ с населённым пунктом, видом работ, фото до/после, метражом (если подтверждён) и кратким описанием. Разделять реальные работы и примеры визуализаций.
- В форме после фактической отправки — подтверждение «Обращение принято», ID только если сервис дал; если доставка уведомления не подтверждена — соответствующий статус для оператора.
- Телефонная кнопка и email сохраняют резервные маршруты. Email-подпись как идентификация компании, не имитировать 24/7 поддержку.
- Доступность, мягкие анимации, быстрые фотографии WebP/AVIF, запрет навязчивых попапов. По Google Core Web Vitals стремиться к LCP ≤2.5c, INP ≤200мс, CLS ≤0.1; измерять, а не объявлять достигнутыми: https://developers.google.com/search/docs/appearance/core-web-vitals .

## Этап 3 — отличительные «плюшки» после появления заявок

- «Покажите свой дом»: фото комнаты/фасада → варианты визуализации трёх стилей **с явной пометкой AI-концепт**, не подменять архитектурный проект.
- «Сравнить варианты»: работа/материалы, базовый/комфорт/премиум, изменение суммы и пояснения.
- PDF-резюме проекта, которое пользователь может скачать без регистрации.
- По договорному объекту: фото-отчёты, этапы, комментарии, документы/согласование, доступ по персональной ссылке; **не включать псевдокабинет**.
- Еженедельная обработка новых обращений по статусам: новое → на связи → замер → смета → договор → отказ. Пилот первых 14 дней без обязательных расходов на CRM.
- В перспективе можно рассмотреть российский backend/CRM и собственный визуализатор; хранение фото с ПДн и юридические условия проверять отдельно.

## Чего не делать

- Не подключать тяжёлый ИИ/3D к загрузке главной страницы.
- Не ставить фальшивый «онлайн», фиктивные отзывы, поддельное количество заявок/строек, непроверенные гарантии, ложное «заявка отправлена».
- Не ставить платную CRM, SMS, телефонию или иностранную SaaS-форму до проверки спроса.
- Не ухудшать проверенный Samsung-звонок.
- Не возвращать дублирующие согласия и лишние CTA в первом экране.

## Критерий успеха

Посетитель на мобильном сайте заходит → выбирает направление → видит предварительную пользу (идея/цена/проект) → вводит имя и телефон только один раз → нажимает одну кнопку → сервис **фактически сохраняет заявку** и уведомляет адрес `kaskad123ai@mail.ru` → посетитель видит честное подтверждение. До реализации этого пути любые визуальные обновления имеют меньший приоритет.
