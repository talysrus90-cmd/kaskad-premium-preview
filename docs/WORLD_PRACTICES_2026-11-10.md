## 2. Что действительно работает в текущем «КАСКАДЕ»

- Четыре направления услуг, качественные реалистичные изображения, четырёхчастная галерея (примерно 144 фото), блок «До/после», шесть этапов работ, FAQ и юридические раскрывающиеся пункты.
- Калькулятор (дом / ремонт, площадь, предварительная стоимость работ без материалов) даёт результат непосредственно на странице.
- Верхняя заметная красная трубка: **проверено владельцем на Samsung**, пакетная команда `ACTION_DIAL` открывает телефон без выбора Сбербанка; для других распознанных устройств используется `tel:`. Не ломать.
- `email-compose.js`: письмо создаётся прямо на сайте, после чего посетитель **сам подтверждает отправку** в Gmail/Mail.ru/Outlook/Яндекс или другой почте.
- Главная форма и формы смарт-раздела сохраняют введённые данные в подготовленное письмо, **но автоматически в почтовый ящик КАСКАДА не отправляют**; backend приёма лидов пока не подключён.
- **Новинка 10.11.2026:** `calculator-share.js`: «Сохранить расчёт» копирует предварительный расчёт и ссылку, которая воспроизводит выбранный тип и площадь. Без передачи имени/телефона в URL. Проверено с `?calc=house&area=150#calculator` на мобильном размере.
- PWA с Service Worker; фотографии загружаются по мере необходимости.
- Нет подтверждённой работоспособной CRM, сервера заявок, цифрового подписания, реального личного кабинета, аналитики конверсий и системы AI-визуализации в публичной версии.

## 3. Приоритеты — минимальные расходы, максимальная польза

### P0. Настоящая отправка заявки — до любой рекламы

Цель: посетитель заполняет имя, телефон, направление и обязательное согласие → одна кнопка «Отправить» → подтверждённое принятие → почтовое уведомление на `kaskad123ai@mail.ru`. Никаких сторонних email-приложений, регистраций посетителя, SMS и двусмысленного «отправлено».

Простой российский вариант: Яндекс Формы в iframe. Официальная документация:
- https://yandex.ru/support/forms/ru/publish — встраивание iframe
- https://yandex.ru/support/forms/ru/send-mail — email-уведомления
- https://yandex.ru/support/forms/ru/pre-fill — предзаполнение полей (из калькулятора)
- https://yandex.ru/support/forms/ru/get-params — параметры для выбранного типа обращения

**Блокер:** на подключённом ПК forms.yandex.ru запросил авторизацию в Яндекс ID. Без входа владельца нельзя создать форму и настроить почту. Нельзя подменять настоящий приём имитацией или секретами в клиентском JavaScript. Перед публикацией проверить 152-ФЗ (оператор, согласие, размещение и обработка персональных данных граждан РФ, антиспам), юрисдикцию хранения и уведомления; протестировать фактическое письмо во «Входящих» и «Спаме».

Сопоставить типовые входы: «Заявка», «Расчёт ремонта», «Расчёт дома», «Задать вопрос». Всё должно приводить к одному техническому приёмнику с разными атрибутами типа обращения. Название кнопки «Отправить заявку» допустимо только после реального подключения.

### P1. Мобильное упрощение форм

Основной минимум: имя + телефон + цель/задача + согласие; площадь, бюджет и срок раскрывать только по желанию. Указывать назначение каждого поля, давать правильную мобильную клавиатуру и отображать ошибки рядом с полем. Не требовать регистрации и email клиента. [Исследования Baymard](https://baymard.com/research-articles/checkout-flow-average-form-fields) подтверждают высокую цену лишних полей и действий; [руководство по мобильным формам](https://baymard.com/research-articles/mobile-checkout) рекомендует понятные подписи над полями.

После получения отправки можно тестировать две короткие версии формы, но не заявлять рост конверсии без данных.

### P1. Сохраняемый расчёт — выполнено

`calculator-share.js?v=20261110-share-v1`: копирование текста и ссылки только с типом объекта и площадью. Пример: `https://talysrus90-cmd.github.io/kaskad-premium-preview/?calc=house&area=150#calculator`. Ссылка не содержит ФИО, телефона, бюджета и подробностей.

### P2. Умная галерея

Короткие фильтры «Дома / Квартиры / Интерьеры / До и после» и возможность выбрать 1–3 понравившихся примера для будущего обращения. В идеале брать фото **реальных работ компании** с подтверждёнными правами; вдохновляющие референсы не выдавать за выполненные объекты. Не добавлять видимые кнопки под каждой картинкой, поскольку пользователь просил компактный дизайн.

### P2. Прозрачный расчёт

Показывать состав работ и исключения; шаг выбора уровня работ («базовый / улучшенный / премиальный») только после согласования реальных диапазонов трудозатрат. **Не менять тарифы и не обещать сроки без подтверждения компании**. Стоимость всегда предварительная и не публичная оферта.

### P2. Доверие без фиктивных обещаний

Реальные короткие примеры «задача → решение → результат», город, вид работ и 2–4 настоящие фотографии, разрешение на использование. Никаких выдуманных отзывов, логотипов партнёров, 5-звёздочных рейтингов, лет опыта и счётчиков объектов. Чёткий статус заявки: «Принято» только после подтверждения сервера.

### P3. Личный кабинет после договора

По защищённой ссылке/авторизации: график, фотоотчёты, документы, согласования, вопросы. Без реального backend не отображать макет как действующий кабинет; не открывать клиентские данные публично.

### P4. AI и 3D-функции

Загрузка фото комнаты → выбранный стиль → реалистичная демонстрация **с пометкой «Концепция»**. Для оценки точности и сметы нужны размеры и спецификация — нейросетевой рендер сам по себе не является измерением. До введения проверить право на изображения, приватность, время генерации на мобильном интернете и экономику модели.

## 4. Производительность: что измерять

Google рекомендует целевые реальные показатели: LCP до 2,5 с, INP до 200 мс, CLS до 0,1 (https://developers.google.com/search/docs/appearance/core-web-vitals). Оценить на реальном Android / медленной сети перед рекламой; не считать результат локального desktop теста полевыми данными.

Сохранять: сжатые адаптивные изображения, lazy-load ниже первого экрана, размеры изображений для снижения CLS, фиксированную навигацию, аккуратные анимации с `prefers-reduced-motion`.

## 5. Контроль качества и приемка

1. Samsung Android: красная трубка → штатный набор без банка (у владельца проверено).
2. iPhone Safari / прочие Android: телефонные ссылки не ведут в ошибку/пустой экран.
3. FAQ, галерея, «до/после», калькулятор и мобильная навигация работают.
4. При сохранении расчёта скопированный текст включает тип, площадь, диапазон, правовую оговорку и рабочую ссылку; открытие ссылки восстанавливает значения.
5. Заявка с главной, калькулятора и смарт-форм: до подключения сервера ясно написано, что это письмо-черновик и его нужно реально отправить.
6. **Перед реальным запуском заявок:** клиент отправляет форму → сервер подтвердил → письмо получено на `kaskad123ai@mail.ru`; тест без согласия не должен отправлять; повторная отправка не дублирует лид; отсутствие сети не создаёт ложного успешного статуса.
7. При любом изменении версионировать assets и `service-worker.js`, проверять опубликованную GitHub Pages версию и браузер на Samsung.

## 6. Правило развития

Сначала **конверсия и доставка обращения**, затем мобильное удобство, портфолио и доверие, только потом AI/VR. Сайт должен оставаться лаконичным: минимум бюрократии, никаких фиктивных функций или платных обязательств без теста.
