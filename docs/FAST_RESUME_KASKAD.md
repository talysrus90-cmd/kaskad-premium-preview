## Не терять согласованный результат

- Главная — компактный сайт «КАСКАД»: строительство домов, ремонт квартир, интерьеры и отделка, проекты/сметы/согласования; реалистичные фотографии; адаптивный мобильный дизайн.
- Убраны три крупные кнопки под первым экраном («Позвонить», «Написать», «Подготовить заявку»), оставлена заметная красная анимированная трубка в правом верхнем углу.
- Телефон компании: +7 928 406-22-12, не показывать цифрами открыто на странице.
- **Работающий вызов Samsung:** непосредственно в `index.html` верхняя трубка с `data-kaskad-call` использует проверенный владельцем Android Intent `action=android.intent.action.DIAL;package=com.samsung.android.dialer`; на Samsung владельца открылось штатное приложение без Сбербанка. `call-routing.js?v=samsung-dial-20261110-v2` сохраняет эту маршрутизацию на Samsung, а для других телефонов использует обычный `tel:`. Не ломать!
- Почта компании: `kaskad123ai@mail.ru`. В нижней части показывать «Электронная почта:» и адрес немного крупнее обычного текста.
- **Новое удобство для посетителей:** `email-compose.js?v=20261110-inpage-v2` перехватывает клики по этому адресу и показывает редактор письма прямо на сайте: адрес получателя уже заполнен, есть тема и текст. Затем посетитель выбирает Gmail, Mail.ru, Outlook, Яндекс или другую почту; выбор почтового приложения (только ID) запоминается в localStorage, в следующие разы не приходится выбирать заново. В Chrome/Android для известных приложений используется package-specific `ACTION_SENDTO` Intent и ссылка на веб-почту как запасной путь. Вызова системного chooser **при нажатии на футер** больше нет. Для «другой почты» `mailto:` может вызвать стандартный chooser, а конкретная почтовая программа может попросить вход.
- При подготовке предварительной заявки кнопка «Открыть письмо для отправки» теперь открывает тот же редактор с готовым текстом. `smart/index.html` также подключает редактор.
- **Важная правовая/техническая граница:** редактор не отправляет письма от имени пользователя автоматически; посетитель должен нажать «Отправить» в своём почтовом приложении. Ни сайт, ни GitHub Pages не могут увидеть email-аккаунты посетителя или отправить письмо без backend и авторизации. Писем на сайте не сохраняем и не объявляем отправленными.
- Отдельная действительно автоматическая отправка заявок из формы без почтового приложения требует подключённого серверного сервиса; на текущем статическом GitHub Pages сервис пока **не подключён**. Перед этим проверить 152-ФЗ, размещение данных граждан РФ на серверах в РФ, согласие и политику, защиту от спама. Один из вариантов для изучения — Яндекс Формы с почтовыми уведомлениями и HTML-встраиванием, но **нет созданной публичной формы и endpoint; не заявлять, что она работает**.
- В FAQ — «Заявка не является публичной офертой» и раскрывающееся согласие на обработку персональных данных. Отдельный дубликат согласия в самом низу убран.
- Кэш PWA: `service-worker.js`, версия `kaskad-pwa-20261110-email-compose-v2`.

## Проверки

- По подтверждению владельца реальный Samsung открыл штатную звонилку без Сбербанка через проверочный Intent; после переноса на главную красную трубку владелец подтвердил успех.
- Браузерный тест мобильного размера проверил открытие email-формы и наличие Gmail/Mail.ru/Outlook/Яндекс/Другой, подставленный адрес, ввод письма.
- Проверено открытие предзаполненного Gmail compose (получатель, тема и тело в URL) и сохранение выбранного сервиса на дальнейшие посещения.
- Версии скриптов менять вместе с service-worker.js и обновлять кэш; GitHub Pages может публиковать коммиты с небольшой задержкой.
- **Подтверждение работы нового email сценария на реальном смартфоне владельца пока не получено**. Не объявлять его полностью проверенным для всех почтовых программ.

## Для следующего чата

Когда пользователь говорит «сайт КАСКАД», работать **именно с этим GitHub-репозиторием и этой ссылкой**, сперва получить текущую `main` версию, не восстанавливать старый HTML-макет, не трогать проверенный Samsung phone intent без крайней необходимости. Изменения коммитить и верифицировать в опубликованной версии; при критических UX изменениях тестировать на Samsung пользователя.
