# КАСКАД — воспроизводимая проверка 3D-фасадов

Работай в репозитории talysrus90-cmd/kaskad-premium-preview. Главная цель — единая отделка дома при вращении, без визуальных противоречий, без ухудшения мобильного UX.

1. Сначала проверь docs/FAST_RESUME_KASKAD.md и docs/3D_FACADE_AUDIT_20261110.md, затем house-3d.source.js. Не исправляй только house-3d.bundle.js: это результат сборки.
2. Фасад: основная коробка facadeBody и оба треугольных фронтона gableFacades используют один экземпляр материала brick и его текущую map. Не добавляй отдельную окраску фронтона. Для каждой стены поддерживай равномерный физический масштаб кирпичной UV-кладки.
3. Различай разную текстуру и разные условия освещения. Проверяй освещение в 09:00, 16:00, 19:30; заднюю стену нельзя оставлять провально чёрной. Естественный объём и тени сохраняй.
4. Проверь все пять фасадов (brick, tuscan, stone, plaster, gray) с четырёх сторон (спереди, справа, сзади, слева). Проверь смену фасада после асинхронной загрузки WebP-текстуры.
5. Запусти: node .agents/skills/kaskad-3d-facade-qa/scripts/check-facade.mjs. Это исходная проверка инвариантов, не замена визуального WebGL-теста.
6. Собери Three.js командой: npx esbuild house-3d.source.js --bundle --minify --platform=browser --format=esm --target=es2022 --outfile=house-3d.bundle.js. Не забывай обновить версии ресурсов в index.html, 3d-house-embed.html, 3d-house.html, service-worker.js.
7. На ширине 390px проверь: вращение/приближение, 12 типов кровли, 11 типов забора, палитры 8+8 цветов, «Обсудить этот вариант», возврат «Назад», автоматическую высоту iframe, 3 качества WebGL. Заявки и согласия нельзя ломать.
8. Для коммерческого сайта публикуй только свои/лицензированные материалы; не называй демонстрационную модель готовым проектом или фотосъёмкой. Проверяй опубликованный GitHub Pages, доступность всех precache-файлов и консоль без ошибок.

## Требуемое подтверждение

В отчёте укажи: 20 проверенных ракурсов, единство материала для тела и фронтонов, все выявленные отклонения, конкретный хеш коммита и адрес опубликованного сайта. Не заявляй «проверено на Redmi», если проверял только эмуляцию мобильного Chromium.

## Мобильный UX v18

Фасад/кровля/забор обновляются раздельными обработчиками, не возвращай повторное обновление всех материалов при выборе забора. В iframe на телефоне 3D сцена закреплена сверху, внутренний список прокручивается отдельно; вспомогательные настройки свернуты в details. Проверка: внутренняя ширина 356px, горизонтальный overflow = 0, первая вкладка Фасад полностью видна, при прокрутке настроек сцена остается сверху, фасад не меняется при смене забора. Подробнее docs/3D_MOBILE_CONFIGURATOR_FIX_20261110.md.
